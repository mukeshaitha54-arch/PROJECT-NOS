# ADR-007: High-Frequency Telemetry Ingestion, Compression & Resilient Buffering

- **Status**: Approved & Verified
- **Date**: July 28, 2026
- **Domain**: Telemetry Ingestion & Transport Infrastructure (`telemetry`, `agent`)

---

## Context
In an enterprise monitoring platform scaling toward 10,000 active infrastructure nodes checking in with heartbeat metrics every 10 seconds and full hardware inventory snapshots every 15 minutes, the system processes massive time-series payload velocities (~86.4 million diagnostic events per day). Transport protocols and backend ingestion pipelines must efficiently consume this flood without triggering network congestion or database storage exhaustion.

## Current Implementation Assessment
The existing backend exposes dedicated telemetry ingestion route controllers under `apps/backend/src/modules/telemetry` and `apps/backend/src/modules/device`, persisting validated snapshots into the `telemetry_snapshots` and `heartbeats` PostgreSQL tables defined in `schema.prisma`. The schema equips these time-series tables with compound indexes on `[deviceId, timestamp(sort: Desc)]` and tenant retention parameters (`organizations.retentionDays`).

## Problem
Uncompressed raw JSON POST payloads continuously transmitting across cellular or remote branch WAN connections consume excessive edge bandwidth. If upstream backend ingestion API instances experience transient reboot cycling or database write lock contention, unbuffered edge agents immediately drop in-flight diagnostic metrics, resulting in gaps in incident historical forensics and false-positive "Node Offline" operator alarms.

## Alternatives Considered
1. **Unbuffered Direct Synchronous Ingestion**: Forcing agents to emit uncompressed raw HTTP JSON payloads directly to database write controllers without retry mechanisms or edge caching.
2. **External Message Broker Architecture**: Directing all agent telemetry via external third-party message queue platforms (e.g., Apache Kafka or RabbitMQ clusters) situated between agents and backend servers.
3. **UDP Datagram Streaming (StatsD/Syslog)**: Streaming unacknowledged UDP packets from edge agents directly into background metric aggregation listeners.

## Decision & Engineering Justification
We **enforce a resilient 14-stage HTTPS Telemetry Ingestion Pipeline equipped with mandatory agent payload compression and offline local disk FIFO buffering**:
1. **Gzip Wire Compression**: Edge monitoring agents compress serialized JSON diagnostic payloads exceeding 1 KB via standard Gzip compression (`Content-Encoding: gzip`), shrinking wire network footprint by ~85%.
2. **Encrypted Local FIFO Disk Queue**: In response to network disconnection or backend 5xx errors, agents automatically transition to `Network_Offline` state, diverting telemetry snapshots into a local encrypted disk FIFO buffer (capped at 50 MB to preserve edge disk capacity). Upon connection recovery, queued items flush sequentially via exponential backoff.
3. **Automated Tenant Retention Pruning**: A scheduled automated cron task evaluates `telemetry_snapshots`, strictly purging legacy rows whose `timestamp` exceeds the owning organization's agreed retention policy (`organizations.retentionDays`), preserving database query performance without manual database administrator intervention.

## Consequences & Migration Impact
- **Positive Benefits**: Reduces network ingestion bandwidth by over 80%; eliminates loss of diagnostic forensic audit history during transient cloud network partitions; prevents time-series storage bloat on standard PostgreSQL servers.
- **Negative Trade-offs**: Increases CPU compression overhead on edge target machines by ~1.2%; requires local storage permission access for agent disk buffering.
- **Migration Impact**: **Zero**. Solidifies existing stable pipeline interfaces and time-series database retention models.
